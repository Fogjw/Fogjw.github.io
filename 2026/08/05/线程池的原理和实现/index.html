线程池的原理和实现

发表于2026-08-05|更新于2026-09-06|学习笔记
|浏览量:

在Cpp并发基础这篇笔记中我们介绍了线程的创建和使用++，这篇笔记，我们将介++绍线程池的原理和实现

线程池的概念

回顾：std::thread在创建后立即创建OS线程运行所分配的任务，在任务运行结束时销毁OS线程，在离开作用域时析构线程对象。在需要频繁创建线程，而线程任务又短时，线程的频繁创建和销毁带来的开销就显得难以忽视。
因此在这种场景下，我们需要使用线程池。

线程池，是一组预先创建好的工作线程加上一个任务队列。当任务队列不空时，线程池中空闲的线程会接取任务执行，执行后回到空闲状态等待下一个任务。在线程池的整个生命周期中，每个线程只创建一次、销毁一次，能够反复利用。
同时，线程池有初始设定的尺寸限制，保证系统同时存在的最大线程数，高并发时，没有线程执行的任务会在队列中等待，虽然这样不能保证任务在短时间内被执行，但是保证了不会出现每个任务都创建线程，导致同时存在大量线程、内存耗尽、系统崩溃的情况。
另外线程池使得任务的提交和执行解耦，提交方只负责把任务提交给线程池，具体任务被哪个线程执行，提交方不在意。

线程池的结构

线程池的核心组件如下：

线程池主要由工作线程集合、任务队列、保护队列的锁、睡眠/唤醒的条件变量组成。

  • 工作线程集合：在线程池初始化时创建N个线程，阻塞在条件变量上
  • 任务队列：提交方将任务加入任务队列，队列不会空时会唤醒空闲的线程接取任务
  • 保护队列的锁：锁保证任务不会同时被多个线程接取
  • 睡眠/唤醒通知：条件变量让线程在队列为空，且stop_为false的时候睡眠
  • 生命周期标志：线程必须在join后析构，而任务队列为空时线程睡眠，不会join，因此必须在stop_为true时唤醒所有线程，完成join后销毁。

线程池的运行流程

  1. 线程池初始化：创建N个线程，每个跑一个消费循环：
  1. 提交任务（Enqueue）：任务入队 + notify_one() 唤醒一个空闲线程
  2. 消费任务：被唤醒的线程取任务执行；执行完把结果放进 future，交给提交方
  3. 关闭：置 stop_ = true + notify_all()（唤醒所有线程让其检查退出条件）+ join() 等全部结束

可变参数模版

  • 为什么需要可变参数模版？

回顾，std::thread构造时如果传入的任务是有参的，则需要传入该任务的参数，比如如果任务为void worker(int x, int y, int z);，那么构造std::thread时可以写std::thread t(worker, 1, 2, 3);，也就是说，构造传入的第一个参数是函数指针，剩余参数为函数需要的参数。

回到当前场景，线程池接受的任务显然是多样的，函数签名不同，所需要的参数类型和个数都不同，因此提交任务的Enqueue方法，必须是可变参数模版。

std::forward与std::move

C++11引入，需要包含头文件<utility>。

两者区别

  • std::move(x)无条件将x变成右值引用
  • std::forward<T>(x)：有条件地转发，x原本是左值则保持左值，原本是右值则保持右值，即“原样传递”。

完美转发

完美转发：模版函数收到什么参数（左值还是右值），就原样把同样的值类别传给下一个函数。

为什么需要完美转发

C++中，有名字的值是左值，所以模板函数收到一个参数 arg，就算外面传的是右值（临时对象），函数体内 arg 依然是左值，这样传出去时就丢失了右值性。丢失右值性就相当于丢失了可以移动资源的机会，也就需要多一次拷贝。

而如果是像这样的话，传入的"hello"和1都是右值，进入模版函数后，std::forward保证它们仍然保持原本右值的特性，这样make_something就不需要再拷贝这两个参数，而是可以直接移动使用这两个参数。

tips：引用折叠（Reference Collapsing）：模板参数 Args&& 里的 && 不是”右值引用”，而是转发引用。实际类型取决于实参：

实参 推导出的 T T&& 折叠结果
左值 int int& int&（左值引用）
右值 int int int&&（右值引用）

一个 T&& 是转发引用，必须同时满足：

  • T 是函数模板的类型参数（不是类模板参数）
  • T 由实参推导出来（不是显式指定、不是依赖类型）
  • 没有 const/volatile 修饰
