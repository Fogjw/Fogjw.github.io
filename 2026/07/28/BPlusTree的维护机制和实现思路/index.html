BPlusTree的维护机制和实现思路

B+树

B+树是一种多路平衡查找树，与B-树的区别在于，B+树将数据都放在叶子节点，非叶子节点只存放索引，这让树的高度更低，磁盘I/O次数更少，同时叶子节点之间相互连接使得B+树范围查询效率也很好。综上因此B+树被广为应用于数据库索引和文件系统。

B+树的结构

B+树由两种节点（叶子节点和非叶子节点）构成，数据只存放在叶子节点，非叶子节点只存放索引。

以存放key-value映射为例，m阶B+树的叶子节点最多存放 (m - 1) 个key-value映射，在节点非根的情况下，叶子节点最少存放 ⌈(m - 1) / 2⌉ 个key-value；非叶子节点最多存放 (m - 1) 个key和 m 个指向子节点的索引，在节点非根的情况下，非叶子节点最少存放 (⌈m / 2⌉ - 1) 个key和 ⌈m / 2⌉ 个指向子节点的索引。以32阶B+树为例，叶子节点最多存放31个key-value，非根叶节点最少存放16个key-value，非叶子节点最多存放31个key和32个索引，非根非叶子节点最少存放15个key和16个索引。B+树保证节点内的key是有序的。

叶子节点之间用指针连接为单链表，B+树维护一个指针指向这个单链表的链表头，用于便于范围查询；同时维护一个指针指向这棵树的根节点，用于查找。

B+树的操作

这里以左开右闭的key范围举例，即规定非叶子节点的第i个索引与第i个key的关系为

  • child(i) < key(i) i == 0
  • key(i - 1) <= child(i) <= key(i) 0 < i < key_count
  • child(i) >= key(i - 1) i == key_count

child(i)表示第i个索引指向的子节点的任意一个key

查找

按key查找value

  1. 获取根节点，若根节点无效则为空树，查找失败。
  2. 若当前节点是叶子节点，遍历/二分查找target_key，有则查找成功返回value，无则不存在这个key，查找失败。
    （遍历还是二分查找取决于m是否大到需要二分查找）
  3. 若当前节点是非叶子节点，遍历/二分查找第一个大于target_key的key，假设是第i个key，则修改当前节点是第i个索引指向的节点，从第2步开始；若没有大于等于target_key的key，则修改当前节点为最后一个索引指向的节点，从2开始。

范围查找(从begin到end)

  1. 获取根节点，若根节点无效则为空树，查找失败。
  2. 按照按key查找value的思路找到第一个key大于等于begin的key-value，从这个key-value开始，遍历这个叶子节点把key-value加入结果集，直到遇到大于end的key或遍历完这个节点
  3. 若遇到大于end的key，则将当前结果集返回
  4. 若遍历完这个节点，则根据叶子节点的next获取下一个叶子节点，继续遍历节点把key-value加入结果集，直到遇到大于end的key或遍历完这个节点，然后执行第3步。

插入

即插入key-value

  1. 按key查找应该插入这个key-value的叶子节点
  2. 插入key-value
  3. 若叶子节点key数量超过(m - 1)，分裂节点，左节点有⌈m/2⌉个key-value，右节点有(m - ⌈m/2⌉)个key-value
  4. 将新分裂出的节点插入叶子节点链表，更新左右节点的子节点的parent，
  5. 更新父节点的索引，指向原叶子节点的索引指向右节点，插入以右节点第一个key和指向左节点的索引
  6. 若父节点key数量插入后超过(m - 1)，分裂节点，将第⌈m/2⌉个key插入父节点的parent，左节点获得该key左边的所有key，右节点获得该key右边的所有key
  7. 更新父节点分裂出的左右节点的子节点的parent
  8. 若父节点的parent插入后key数量再次超过(m - 1)，继续分裂，直到不触发分裂或分裂根节点
  9. 若分裂根节点，新增根节点指向原根节点分裂出的两个节点

删除

  1. 按key查找应该插入这个key-value的叶子节点
  2. 删除key-value
  3. 若当前节点非根且key数量少于最少标准，则通过parent找到右边的节点，如果右边叶子节点key数大于最小标准，移动一个key到当前节点，同时更新父节点的分隔key，如果右边叶子节点key数小于等于最小标准，合并当前节点和右边的节点
  4. 如果没有右边节点，通过parent找到左边的节点，如果左边叶子节点key数大于最小标准，移动一个key到当前节点，同时更新父节点的分隔key，如果左边叶子节点key数小于等于最小标准，合并当前节点和左边的节点
  5. 合并使父节点的key减少，如果key数不足，同样先尝试借key，借key不成则合并，向上递归
  6. 检查根节点是否有至少2个child，没有则对根节点降级

一些经验

B+树的实际编写非常考虑细节，尤其有非常多的索引边界问题，分支众多，建议在编写的时候多加注意，多写assert断言。加上由于叶子节点和非叶子节点的数据结构和处理不同，一般需要多个辅助函数协同构成一个功能。
同时B+树的节点内最多key数和最少key数也不必死守，如在严格定义下，32阶B+树叶子节点满分裂后为两个16key的叶子节点，此时如果删除1个key又将合并节点，节点的分裂和合并逻辑都是复杂的、开销大的，因此可以适当放松规则，如设置低于15key才进行借key或合并，这样一来就能在不明显影响树结构的情况下减少磁盘I/O抖动。
